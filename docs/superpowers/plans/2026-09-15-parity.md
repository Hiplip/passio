# Feature parity — implementation plan

> **Deviation from the usual plan format, stated up front:** this plan is being
> written and executed by the same agent in one unattended run, so it is a
> working sequence rather than a document for a stranger. It names every file,
> every test, and the order things must happen in — but it does not transcribe
> code that is about to be written anyway. Anything BLOCKED or deviated from is
> recorded at the bottom as it happens.

**Goal:** close the functional gap against Bitwarden and 1Password, per
`docs/superpowers/specs/2026-09-15-parity-design.md`.

**Rule for every phase:** all five gates green, schema pushed to both Neon
branches if it changed, committed and pushed on its own.

---

## Phase 1 — Schema foundations

The one that must go first: everything else writes items, and items whose shape
changes later are a migration nobody can perform server-side.

**Files**
- `packages/core/src/schema.ts` — custom fields, URI entries, history,
  favourites, fifteen new item types
- `packages/core/src/schema.test.ts` — extend
- `packages/core/src/uri.ts` + test — match-mode evaluation, extracted from
  `match.ts`
- `packages/core/src/match.ts` — consume `uri.ts`, keep the PSL behaviour
- `packages/core/src/history.ts` + test — append-on-change, cap at ten
- `packages/vault-ui/src/item-form.tsx` — editors for the new types
- `packages/vault-ui/src/custom-fields.tsx` — add/remove/reorder

**Steps**
1. `customFieldSchema`, `uriEntrySchema`, `historyEntrySchema`
2. Add `fields`, `uris`, `history`, `favourite` to `commonFields` where they
   belong; keep legacy `uri` readable
3. Fifteen new members of the discriminated union, each with `newXItem()`
4. `uri.ts`: `matchesUri(entry, pageUrl)` for all six modes
5. `match.ts` delegates, keeping `allowPrivateDomains` and its test
6. `history.ts`: `recordPasswordChange(item, next)` 
7. Tests: every type round-trips through encrypt/decrypt; every match mode
   table-driven; history caps and dedupes
8. UI: a generic field renderer driven by a per-type field table, so adding a
   type is data rather than JSX

## Phase 2 — Import and export

The adoption unlock. Nobody retypes two hundred passwords.

**Files**
- `packages/core/src/import/` — `index.ts`, `bitwarden.ts`, `onepassword.ts`,
  `lastpass.ts`, `chrome.ts`, `csv.ts`, plus a shared `csv-parse.ts`
- `packages/core/src/export/` — `index.ts`, `encrypted.ts`, `plain.ts`, `csv.ts`
- Tests per format, with fixtures including malformed input
- `apps/web/src/app/settings/data/` — import and export screens

**Steps**
1. A correct CSV reader first — quoted fields, embedded commas, CRLF, BOM.
   Everything else depends on it and a naive `split(",")` loses data.
2. One parser per format → `{ items, folders, warnings }`
3. Anything with no home becomes a custom field; anything unrepresentable
   becomes a warning naming the item. Never silently drop.
4. Duplicate detection by (title, username, first URI) — reported, not merged
5. Export: encrypted (own KDF params embedded), plaintext, CSV
6. Round-trip test: export → import → identical vault
7. Web UI for both, with the plaintext export behind an explicit confirmation

## Phase 3 — Matching and autofill

**Files**
- `apps/extension/src/fields.ts` — card and identity detection
- `apps/extension/src/inject.ts` — payload becomes a typed record
- `apps/extension/src/excluded.ts` + test — per-domain opt-out
- `packages/core/src/match.ts` — consume match modes

**Steps**
1. Extend field detection: `autocomplete` attributes first, heuristics second
2. Fill payload from three strings to a record keyed by field role
3. Excluded domains, stored in `chrome.storage.local`, enforced in the overlay
   and the popup
4. Tests: card and identity fixtures in `fields.test.ts`; exclusion logic

## Phase 4 — Health and breach

**Files**
- `packages/core/src/strength.ts` + test — local scoring
- `packages/core/src/health.ts` + test — weak, reused, old, unsecured
- `packages/core/src/breach.ts` + test — HIBP k-anonymity, injected fetcher
- `packages/vault-ui/src/health-report.tsx`

**Steps**
1. Strength scoring: length, classes, repeats, sequences, common patterns
2. Health analysis over decrypted items
3. Breach: SHA-1, five-character prefix, local suffix match; unreachable must
   degrade to "unknown", never "safe"
4. Report UI, and an opt-in toggle for the only outbound call in the product

## Phase 5 — Vault management

Favourites, sort orders, bulk select, per-item reprompt enforced in custody,
generator history, username generator.

## Phase 6 — Multi-tenancy and keypair

Remove the single-owner gate. Add `publicKey` and `wrappedPrivateKey` to `user`.
Schema change — push to **both** Neon branches and verify against
`information_schema`.

## Phase 7 — Firefox

`firefox-mv3` target in WXT. Manifest assertions for both targets.

## Phase 8 — Save and update prompts

Content script watches for submitted credentials; offers to save or update.
Cannot be verified without a browser — goes on the handoff list.

## Run log

**Completed:** phases 1, 2, 3, 4, 5, and the multi-tenancy half of 6.
Six commits, `2ec1a48` … `2135269`, all pushed and deployed. 636 → 814 tests.

**Deviations and stops:**

- **Phase 7 (Firefox) STOPPED, not completed.** The build succeeds and the
  artifact cannot work: offscreen documents are a Chromium API, so
  `chrome.offscreen.createDocument` is undefined on Firefox and the first unlock
  throws. Shipping an extension that installs and then cannot open the vault is
  worse than shipping none. Groundwork left in `wxt.config.ts`; the build script
  was removed so it cannot be shipped by accident. Making it real means
  relocating custody into the background script — a phase of its own, on the
  most trust-critical wiring in the project.
- **Phase 6 half done.** Multi-tenancy landed, gated by `REGISTRATION_OPEN` and
  defaulting to closed. The per-user keypair did NOT: it is X25519 generation,
  wrapping a private key under the vault key, and a migration path for the
  existing account. Cheapest now while there is one vault rather than a hundred,
  but not something to rush at the end of an unattended run. First thing to pick
  up.
- **Phase 8 (save and update prompts) not started.** Ran out of run before it.
- A `parsePassioCsv` importer was added that the plan did not call for, because
  the export round-trip test found that our own CSV export could not be read by
  any of our importers.

**Handoff:** `docs/PARITY-HANDOFF.md`.
